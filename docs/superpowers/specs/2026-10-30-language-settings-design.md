# Language settings design — VI and EN

User requests a persisted choice of Vietnamese and English. Extend existing1.2.0 UI, no translation of captured data and no external services. Default vi preserves old installs; only supported values vi/en, normalize invalid/missing tovi. The language selector is in Settings, shows self-names Tiếng Việt / English, is saved by existing Save button; reset restores vi. Preference uses dedicated chrome.storage.local key meetscribe_setting_language plus legacy settings migration; concurrent independent preference saves must not overwrite it.

All application-owned visible labels, button/tooltip/ARIA text, document titles, statuses, empty states, prompts/confirms, notifications and recoverable errors in Settings, Library, toolbar and worker/offscreen paths have VI/EN coverage. Saving changes already-open pages/toolbar without restarting an active capture or losing buffer, picker selection, unsaved rename/search or file data. Dates format per chosen locale. Captions, titles typed by user, folder names, error details from native browser and data identifiers/JSON fields remain intact. Generated transcript/AI instruction headings may follow selected language; raw fields/filenames/paths remain stable. Existing persisted VI errors should be readable in EN by translating known message templates only at explicit error-display boundaries. Never translate arbitrary DOM/user data.

Use no dependencies or network: a pure classic-script shared i18n API plus wrapper for module contexts and three independent catalogs ui./toolbar./system. A module wrapper imports all catalogs statically (Chrome service workers forbid dynamic import). Injection includes i18n core/catalogs before content.js, including Zoom frames. Do not use runtime JSON fetches, eval, innerHTML translation, broad DOM auto-translation or global mock/test-only fallbacks in production. Static HTML translation only uses explicit data-i18n attributes. Locale catalog parity, interpolation and default migration are tested.

Release1.3.0 updates package/lock/manifest/badges/changelogs/guides/screenshots. Chrome manifest name/description/action use native _locales vi/en if practical; explicit app language controls app surfaces and action title, Chrome-managed install strings follow browser locale. Language is not a new caption language selector. Testing must cover real unpacked extension VI->EN->VI across open Settings/Library/toolbar, storage reload/reset, EN during active recording, final-caption drain and invalid old settings, representative errors/dynamic counts/XSS. Preserve current61unit/22browser baseline and all extension tests; update injection fixtures intentionally.
